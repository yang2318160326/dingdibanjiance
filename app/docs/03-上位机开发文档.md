# 上位机开发文档 -- 安卓APP设计

> 版本: V2.0  
> 日期: 2026-06-04  
> 目标平台: Android API 26+  
> 开发语言: Kotlin  
> UI框架: Jetpack Compose + Material 3  
> 更新说明: 支持多设备管理, 依次连接各台下位机

## 1. APP架构

### 1.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| UI层 | Jetpack Compose + Material 3 | 声明式UI |
| 导航 | Navigation Compose | 屏幕路由 |
| 状态管理 | ViewModel + StateFlow | MVVM |
| 依赖注入 | Hilt | 管理依赖 |
| BLE通信 | Nordic BLE Library 2.7+ | 蓝牙连接 |
| 本地数据库 | Room | 多设备数据存储 |
| 协程 | Kotlin Coroutines + Flow | 异步操作 |

class BleConnectionManager @Inject constructor(
    private val context: Context
) {
    val connectionState: StateFlow<BleConnectionState>
    val scanResults: StateFlow<List<BleScanResult>>
    val currentDevice: StateFlow<ConnectedDevice?>

    fun startScan()
    fun stopScan()
    fun connect(device: BleScanResult)
    fun disconnect()

    suspend fun sendCommand(cmd: ByteArray): ByteArray
    suspend fun sendData(data: ByteArray, onProgress: (Float) -> Unit)
}

sealed class BleConnectionState {
    object Disconnected : BleConnectionState()
    object Scanning : BleConnectionState()
    object Connecting : BleConnectionState()
    data class Connected(val deviceName: String, val macAddress: String) : BleConnectionState()
    data class Error(val message: String) : BleConnectionState()
}

data class BleScanResult(
    val name: String,
    val macAddress: String,
    val rssi: Int
)

data class ConnectedDevice(
    val name: String,
    val macAddress: String,
    val deviceId: Long,
    val firmwareVersion: String
)

### 3.2 已知设备管理 (新增)

```kotlin
/**
 * 已知设备 - 记录用户连接过的设备
 */
@Entity(tableName = "known_devices")
data class DeviceEntity(
    @PrimaryKey
    val macAddress: String,         // BLE MAC地址 (唯一标识)
    val customName: String,         // 用户自定义名称
    val deviceId: Long,             // 设备端ID
    val firstSeen: Long,            // 首次连接时间
    val lastConnected: Long,        // 最后连接时间
    val recordCount: Int,           // 本地存储的记录数
    val notes: String               // 用户备注
)

@Dao
interface DeviceDao {
    @Query("SELECT * FROM known_devices ORDER BY lastConnected DESC")
    fun getAllDevices(): Flow<List<DeviceEntity>>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsert(device: DeviceEntity)

    @Delete
    suspend fun delete(device: DeviceEntity)

    @Query("UPDATE known_devices SET lastConnected = :time, recordCount = :count WHERE macAddress = :mac")
    suspend fun updateLastSeen(mac: String, time: Long, count: Int)
}
```

## 4. 多设备操作流程

### 4.1 连接新设备流程

```
1. 用户点击"扫描"
2. APP启动BLE扫描
3. 列表显示发现的设备 (名称+MAC+信号强度)
4. 用户选择一台设备, 点击"连接"
5. APP建立BLE连接, MTU协商
6. APP发送PING命令, 获取设备信息
7. APP将设备信息保存到known_devices表
8. 进入DeviceScreen, 显示设备信息
9. 用户可进行配置/下载操作
10. 操作完成后, 用户点击"断开连接"
11. APP断开BLE, 回到设备列表
12. 用户可选择连接下一台设备
```

### 4.2 重新连接已知设备流程

```
1. APP启动时加载known_devices列表
2. 用户从已知设备列表选择一台
3. APP启动BLE扫描 (或直接尝试连接已知MAC)
4. 发现设备后自动连接
5. 后续流程同上
```

### 4.3 数据下载流程 (单设备)

```
1. 用户在DeviceScreen点击"下载数据"
2. APP发送GET_INFO获取记录总数
3. APP发送GET_DATA [StartIndex=本地已有数, Count=剩余数]
4. 设备逐片发送DATA_FRAG
5. APP逐片确认DATA_ACK
6. 接收的记录存入Room数据库 (deviceId=当前设备MAC)
7. 下载完成, 更新已知设备记录数
```
