# 传感器读取协议文档 -- Modbus RTU

> 版本: V2.0  
> 日期: 2026-06-04  
> 协议: Modbus RTU (RS485)  
> 更新说明: 一台下位机对应一个传感器 (1:1), 去除多传感器轮询

---

## 1. Modbus RTU协议概述

### 1.1 物理层

| 参数 | 值 |
|------|------|
| 接口标准 | RS485半双工 |
| 波特率 | 9600 bps (可配置: 1200/2400/4800/9600/19200/38400/115200) |
| 数据位 | 8位 |
| 校验位 | 无/奇/偶 (可配置, 默认无) |
| 停止位 | 1位 |
| 字节序 | 大端序 (Big-Endian) |
| 最大从站数 | 247 (地址1-247) |
| 总线长度 | 最大1200米 (推荐<500米) |

### 1.2 帧时序

```
┌──────────────────────────────────────────────────────┐
│                    Modbus RTU 帧                      │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┤
│ Addr │ Func │ Data │ Data │ ...  │ Data │ CRCL │ CRCH │
│ 1B   │ 1B   │ 1B   │ 1B   │      │ 1B   │ 1B   │ 1B   │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘

帧间沉默: ≥ 3.5个字符时间 (9600bps时约3.65ms)
字符间沉默: ≤ 1.5个字符时间 (9600bps时约1.56ms)
```

### 1.3 通信模式

```
主站 (STM32)                         从站 (传感器)
    │                                    │
    │── 请求帧 (功能码+数据) ──────────▶│
    │                                    │
    │                              处理请求
    │                                    │
    │◀── 响应帧 (功能码+数据) ──────────│
    │                                    │
    │  (等待T3.5帧间沉默)                │
    │                                    │
    │── 下一个请求 ────────────────────▶│
```

## 2. 功能码定义

### 2.1 本系统使用的功能码

| 功能码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x03 | 读保持寄存器 | 主→从 | 读取传感器数据 (主要使用) |
| 0x04 | 读输入寄存器 | 主→从 | 读取传感器数据 (部分传感器) |
| 0x06 | 写单个寄存器 | 主→从 | 配置传感器参数 (可选) |

### 2.2 功能码0x03 -- 读保持寄存器

#### 请求帧格式

```
+--------+--------+------------+------------+------------+------------+
| Addr   | Func   | StartAddr  | StartAddr  | Quantity   | Quantity   |
| 1B     │ 0x03   │ Hi (1B)    │ Lo (1B)    │ Hi (1B)    │ Lo (1B)    |
+--------+--------+------------+------------+------------+------------+

Addr:      从站地址 (1-247)
Func:      功能码 0x03
StartAddr: 起始寄存器地址 (0x0000-0xFFFF), 大端序
Quantity:  读取数量 (1-125), 大端序

总长度: 8字节 (不含CRC)
```

#### 正常响应帧格式

```
+--------+--------+----------+--------+--------+-----+--------+--------+
| Addr   | Func   | ByteCount| DataHi | DataLo | ... | CRCLo  | CRCHi  |
| 1B     │ 0x03   │ 1B       │ 1B     │ 1B     │     │ 1B     │ 1B     |
+--------+--------+----------+--------+--------+-----+--------+--------+

ByteCount: 数据字节数 = Quantity * 2
Data:      寄存器值, 每个2字节, 大端序

总长度: 3 + Quantity*2 + 2 字节
```

#### 异常响应帧格式

```
+--------+--------+-------------+--------+--------+
| Addr   | Func   | ExceptionCode | CRCLo  | CRCHi  |
| 1B     │ 0x83   │ 1B          │ 1B     │ 1B     |
+--------+--------+-------------+--------+--------+

Func:          功能码 + 0x80 (0x83)
ExceptionCode: 异常码

总长度: 5字节
```

#### 通信示例

**示例1: 读取传感器1的保持寄存器0-3 (温度、湿度等)**

```
请求: 01 03 00 00 00 04 [CRC16]
      │  │  └──┘  └──┘
      │  │   起始  数量
      │  功能码
      从站地址

正常响应: 01 03 08 09 29 1A 85 0B B8 05 DC [CRC16]
          │  │  │  └─────────────────────┘
          │  │  │   4个寄存器值 (各2字节):
          │  │  │   reg0=0x0929=2345 (温度*10)
          │  │  │   reg1=0x1A85=6789 (湿度*10)
          │  │  │   reg2=0x0BB8=3000 (压力)
          │  │  │   reg3=0x05DC=1500 (光照)
          │  │  字节数=8
          │  功能码
          从站地址

异常响应: 01 83 02 [CRC16]
          │  │  └─ 异常码: 非法数据地址
          │  功能码+0x80
          从站地址
```

**示例2: 读取传感器2的输入寄存器0-1**

```
请求: 02 04 00 00 00 02 [CRC16]

正常响应: 02 04 04 41 20 00 00 [CRC16]
          │  │  │  └─────────┘
          │  │  │   1个FLOAT32值:
          │  │  │   0x41200000 = 10.0f
          │  │  字节数=4
          │  功能码
          从站地址
```

### 2.3 功能码0x04 -- 读输入寄存器

帧格式与功能码0x03完全相同, 仅功能码字节不同 (0x04 vs 0x03)。

输入寄存器通常用于只读数据 (如传感器测量值), 保持寄存器可用于读写 (如配置参数)。

### 2.4 功能码0x06 -- 写单个寄存器

#### 请求帧格式

```
+--------+--------+------------+------------+------------+------------+
| Addr   | Func   | RegAddr    | RegAddr    | RegValue   | RegValue   |
| 1B     │ 0x06   │ Hi (1B)    │ Lo (1B)    │ Hi (1B)    │ Lo (1B)    |
+--------+--------+------------+------------+------------+------------+

RegAddr:   寄存器地址 (0x0000-0xFFFF)
RegValue:  写入值 (0x0000-0xFFFF)
```

#### 正常响应帧

响应帧与请求帧完全相同 (回显)。

## 3. 异常码定义

| 异常码 | 名称 | 说明 | 处理方式 |
|--------|------|------|----------|
| 0x01 | 非法功能码 | 从站不支持请求的功能码 | 检查传感器规格书 |
| 0x02 | 非法数据地址 | 请求的寄存器地址不存在 | 检查寄存器映射表 |
| 0x03 | 非法数据值 | 请求的寄存器数量超出范围 | 减少读取数量 |
| 0x04 | 从站设备故障 | 传感器内部错误 | 重试或更换传感器 |
| 0x05 | 确认 | 从站正在处理长命令 | 等待后查询 |
| 0x06 | 从站设备忙 | 从站正在处理其他命令 | 等待后重试 |
| 0x08 | 内存奇偶性错误 | 从站存储器错误 | 重试或更换传感器 |
| 0x0A | 不可用网关路径 | 网关配置错误 | 检查网络配置 |
| 0x0B | 网关目标设备无响应 | 目标设备离线 | 检查设备状态 |

## 4. CRC16计算

### 4.1 算法说明

Modbus RTU使用CRC16校验, 参数如下:

| 参数 | 值 |
|------|------|
| 名称 | CRC-16/Modbus |
| 多项式 | 0x8001 (反转形式: 0xA001) |
| 初始值 | 0xFFFF |
| 输入反转 | 是 (LSB First) |
| 输出反转 | 是 |
| 最终异或 | 0x0000 |

### 4.2 计算范围

CRC16计算范围为帧中除CRC本身以外的所有字节:

```
[Addr][Func][Data...]  ← 计算这N个字节
                     [CRCL][CRCH]  ← 得到这两个字节
```

### 4.3 C语言实现

```c
/**
 * @brief 计算Modbus CRC16
 * @param data  数据指针
 * @param len   数据长度
 * @return CRC16值 (小端序排列: 低字节在前)
 */
uint16_t Modbus_CRC16(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;

    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001) {
                crc = (crc >> 1) ^ 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }

    return crc;
}

/**
 * @brief 构建带CRC的Modbus请求帧
 * @param buf       输出缓冲区
 * @param slave_addr 从站地址
 * @param func      功能码
 * @param reg_addr  寄存器地址
 * @param quantity  数量
 * @return 帧总长度 (字节)
 */
uint16_t Modbus_BuildRequest(uint8_t *buf, uint8_t slave_addr,
                              uint8_t func, uint16_t reg_addr,
                              uint16_t quantity)
{
    buf[0] = slave_addr;
    buf[1] = func;
    buf[2] = (reg_addr >> 8) & 0xFF;
    buf[3] = reg_addr & 0xFF;
    buf[4] = (quantity >> 8) & 0xFF;
    buf[5] = quantity & 0xFF;

    uint16_t crc = Modbus_CRC16(buf, 6);
    buf[6] = crc & 0xFF;        // CRC低字节
    buf[7] = (crc >> 8) & 0xFF; // CRC高字节

    return 8;
}
```

### 4.4 CRC校验验证

**已知帧的CRC计算示例:**

```
帧: 01 03 00 00 00 04
计算CRC16:
  初始: 0xFFFF
  XOR 0x01: 0xFFFE
  ... (逐字节计算)
  结果: 0xC40B
  小端序输出: 0B C4

完整帧: 01 03 00 00 00 04 0B C4
```

## 5. 传感器数据解析

### 5.1 常见传感器寄存器映射

#### 温湿度传感器 (如 SHT30 Modbus模块)

| 寄存器地址 | 名称 | 单位 | 比例因子 | 数据类型 |
|------------|------|------|----------|----------|
| 0x0000 | 温度 | °C | ÷10 | INT16 |
| 0x0001 | 湿度 | %RH | ÷10 | UINT16 |

```
读取: 01 03 00 00 00 02 [CRC]
响应: 01 03 04 00 E1 02 8A [CRC]
      温度 = 0x00E1 = 225 → 22.5°C
      湿度 = 0x028A = 650 → 65.0%RH
```

#### 压力传感器 (如 气压模块)

| 寄存器地址 | 名称 | 单位 | 比例因子 | 数据类型 |
|------------|------|------|----------|----------|
| 0x0000 | 压力高位 | - | - | UINT16 |
| 0x0001 | 压力低位 | - | - | UINT16 |

```
32位压力值 = (reg[0] << 16) | reg[1]
实际压力 = 值 / 100.0 (kPa)
```

#### 多参数水质传感器

| 寄存器地址 | 名称 | 单位 | 比例因子 | 数据类型 |
|------------|------|------|----------|----------|
| 0x0000 | 温度 | °C | ÷10 | INT16 |
| 0x0001 | pH值 | pH | ÷100 | UINT16 |
| 0x0002 | 溶解氧 | mg/L | ÷100 | UINT16 |
| 0x0003 | 电导率 | μS/cm | ÷1 | UINT16 |
| 0x0004 | 浊度 | NTU | ÷1 | UINT16 |
| 0x0005 | ORP | mV | ÷1 | INT16 |

### 5.2 数据类型转换

#### UINT16 (无符号16位)

```c
uint16_t value = (reg_hi << 8) | reg_lo;
// 或直接使用寄存器值
float real_value = value / scale_factor;
```

#### INT16 (有符号16位)

```c
int16_t value = (int16_t)((reg_hi << 8) | reg_lo);
float real_value = value / scale_factor;
```

#### UINT32 (无符号32位, 2个寄存器)

```c
uint32_t value = ((uint32_t)reg[0] << 16) | reg[1];
float real_value = value / scale_factor;
```

#### FLOAT32 (IEEE754浮点, 2个寄存器)

```c
// 方式1: 使用联合体
typedef union {
    uint32_t u32;
    float f32;
} FloatConvert_t;

FloatConvert_t conv;
conv.u32 = ((uint32_t)reg[0] << 16) | reg[1];
float value = conv.f32;

// 方式2: 使用memcpy
uint32_t raw = ((uint32_t)reg[0] << 16) | reg[1];
float value;
memcpy(&value, &raw, 4);
```

## 6. RS485总线管理

### 6.1 总线拓扑 (1:1 点对点连接)

本系统采用一台下位机连接一个传感器的点对点拓扑:

```
    STM32下位机                         传感器
    ┌──────────────┐                   ┌──────────┐
    │  MAX3485     │    RS485双绞线    │          │
    │  ┌─────┐     │                   │          │
    │  │ DE  │ ← PA4                   │          │
    │  │ RO  │ → PA3 ──── A ──────────┤ A        │
    │  │ DI  │ ← PA2 ──── B ──────────┤ B        │
    │  └─────┘     │                   │          │
    └──────────────┘                   └──────────┘

    无需终端电阻 (点对点短距离, <15米)
    如距离较远(>50米), 建议加120Ω终端电阻
```

**与多传感器总线的区别:**
- 点对点连接, 无需总线仲裁
- 传感器地址固定 (配置中设定), 通常为1
- 无需终端电阻 (短距离)
- 接线简单, 只需A/B两根线

### 6.2 方向控制时序

```
                    发送流程
    ┌─────────────────────────────────────────┐
    │                                         │
    │  DE=HIGH (切换到发送模式)                │
    │  │                                      │
    │  │  ┌─ 等待1个位时间 (约104μs@9600bps) ─┐│
    │  │  │                                   ││
    │  ▼  ▼                                   ││
    │  ┌─────────────────────────────────┐    ││
    │  │ UART发送请求帧数据              │    ││
    │  └─────────────────────────────────┘    ││
    │                                         ││
    │  UART发送完成                            ││
    │  │                                      ││
    │  │  ┌─ 等待最后一个字节发送完毕 ─────────┐││
    │  │  │ (约1ms)                           │││
    │  ▼  ▼                                   │││
    │  DE=LOW (切换到接收模式)                 ││
    │                                         ││
    └─────────────────────────────────────────┘

                    接收流程
    ┌─────────────────────────────────────────┐
    │                                         │
    │  DE=LOW (接收模式)                       │
    │  │                                      │
    │  ▼                                      │
    │  ┌─────────────────────────────────┐    │
    │  │ UART接收响应帧数据              │    │
    │  │ (超时: 100ms无数据=超时)        │    │
    │  └─────────────────────────────────┘    │
    │                                         │
    │  接收完成, 解析响应                      │
    │                                         │
    └─────────────────────────────────────────┘
```

### 6.3 点对点通信

本系统为点对点连接 (1台STM32 ↔ 1个传感器), 无需总线仲裁:
- 主站(STM32)只与一个从站通信
- 发送请求后立即切换到接收模式
- 等待响应后进行下一次采集

### 6.4 终端电阻

| 场景 | 是否需要终端电阻 | 说明 |
|------|------------------|------|
| 短距离 (<50米) | 不需要 | 点对点连接, 信号反射可忽略 |
| 长距离 (>50米) | 建议加 | 两端各120Ω, 减少信号反射 |

## 7. 错误处理

### 7.1 超时处理

```c
#define MODBUS_TIMEOUT_MS    100     // 响应超时时间
#define MODBUS_RETRY_COUNT   3       // 重试次数

int Modbus_ReadWithRetry(uint8_t addr, uint16_t reg, uint16_t count,
                          uint16_t *values)
{
    for (int retry = 0; retry < MODBUS_RETRY_COUNT; retry++) {
        int ret = Modbus_ReadHoldingRegisters(addr, reg, count,
                                                values, MODBUS_TIMEOUT_MS);
        if (ret > 0) {
            return ret;  // 成功
        }
        HAL_Delay(10);   // 重试前短延时
    }
    return APP_ERR_TIMEOUT;  // 所有重试失败
}
```

### 7.2 常见错误和处理

| 错误现象 | 可能原因 | 处理方式 |
|----------|----------|----------|
| 无响应 | 传感器未上电/地址错误/总线断开 | 检查硬件, 验证地址 |
| CRC错误 | 总线干扰/波特率不匹配 | 检查接线, 降低波特率 |
| 异常码0x02 | 寄存器地址不存在 | 检查传感器手册 |
| 异常码0x03 | 读取数量超出范围 | 减少单次读取数量 |
| 响应数据异常 | 数据类型不匹配 | 检查数据类型设置 |

### 7.3 超时计算

```
字符传输时间 = 11位 / 波特率 (1起始+8数据+1校验+1停止)

9600bps时:  11/9600 = 1.146ms/字符
19200bps时: 11/19200 = 0.573ms/字符

帧间沉默 T3.5 = 3.5 × 1.146ms = 4.01ms (9600bps)

最大响应时间:
  请求帧: 8字节 × 1.146ms = 9.17ms
  T3.5沉默: 4.01ms
  传感器处理: ~50ms (典型值)
  响应帧: 15字节 × 1.146ms = 17.19ms
  T3.5沉默: 4.01ms
  总计: ~84ms

建议超时设置: 100ms (9600bps), 50ms (19200bps)
```

## 8. 单传感器采集策略

### 8.1 采集流程

本系统每台下位机只连接一个传感器, 采集流程简化:

```
配置: Addr=1, StartReg=0, RegCount=4, DataType=UINT16

采集步骤:
  1. 发送Modbus请求 (Addr=1, FC03, Start=0, Count=4)
  2. 等待传感器响应 (超时100ms)
  3. 解析响应数据
  4. 打包成SensorRecord_t存储到Flash
  5. 完成, 进入低功耗睡眠等待下次采集
```

### 8.2 时间估算

```
单次采集总时间:
  请求发送: 8字节 × 1.146ms = 9.17ms
  帧间沉默: 4.01ms
  响应等待: ~50ms (传感器处理)
  响应接收: 15字节 × 1.146ms = 17.19ms
  帧间沉默: 4.01ms
  数据打包+Flash写入: ~5ms
  总计: ~90ms

结论: 采集间隔最小约1秒即可满足需求
      实际间隔由配置决定 (0~24小时)
```

### 8.3 与多传感器方案的对比

| 项目 | 旧方案 (多传感器) | 新方案 (单传感器) |
|------|-------------------|-------------------|
| 采集时间 | 252ms~数秒 (3~10个) | ~90ms (1个) |
| 配置复杂度 | 需要传感器表 | 单组参数 |
| Modbus地址 | 多个地址轮询 | 固定1个地址 |
| 功耗 | 较高 (多次通信) | 较低 (单次通信) |
| 记录结构 | 多传感器混合 | 单一传感器数据 |
